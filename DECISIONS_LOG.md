- 18:40 - User tested the live deploy and found two real bugs: (1) toolbar bold/italic/etc. didn't show "active" until the next keystroke - Tiptap v3's `useEditor` only re-renders the component that owns the hook on document-changing transactions; a selection-only change (or toggling a mark with no text selected) never propagated to `Toolbar`. Fixed with `useEditorState` (Tiptap v3's selector-based reactive hook), which re-renders on every transaction, selection-only included. (2) "Load latest" did nothing - it called `router.refresh()`, which re-renders the Server Component but Tiptap's `content` option is read only once at editor creation, so new props never reach the live ProseMirror doc. Fixed by using the document already returned in the 409 response body directly: `editor.commands.setContent(latest.contentHtml, { emitUpdate: false })` plus syncing title/version client-side - no extra request, no websockets needed (the brief's "409 instead of silently overwriting" requirement is satisfied by catching the conflict on the *next* save attempt, not by live sync, which is explicitly out of scope).
